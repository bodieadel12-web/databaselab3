Q1.1 Insert a row in the DEPARTMENT table that references a row in the EMPLOYEE table. Then try to delete the referenced row. What will happen?

SQL Used:
INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno) VALUES ('12345', 'Ali', 'Ahmed', '1990-01-01', 'Cairo', 'M', 5000.00, 1);
INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date) VALUES (1, 'IT', '12345', '2023-01-01');
DELETE FROM EMPLOYEE WHERE ssn = '12345';

Output / Error:
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`company`.`department`, CONSTRAINT `department_ibfk_1` FOREIGN KEY (`mgr_ssn`) REFERENCES `employee` (`ssn`))
Explanation: MySQL rejects the deletion because the employee row is actively referenced as a foreign key by the department table, preserving referential integrity.


Q1.2 Insert a row in the PROJECT table that references a row in the DEPARTMENT table that doesn't exist yet. What will happen?

SQL Used:
INSERT INTO PROJECT (Pnumber, Pname, Plocation, Dno) VALUES (101, 'AI System', 'Alexandria', 999);

Output / Error:
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`company`.`project`, CONSTRAINT `project_ibfk_1` FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))
Explanation: Referential integrity rules prevent inserting a child foreign key value that does not match an existing primary key in the referenced parent table.


Q1.3 If mgr_ssn and Dno are both NOT NULL, how will you insert the first row in EMPLOYEE or DEPARTMENT?

SQL Used:
SET FOREIGN_KEY_CHECKS = 0;
INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno) VALUES ('11111', 'Omar', 'Hassan', '1985-05-12', 'Giza', 'M', 7000.00, 1);
INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date) VALUES (1, 'HR', '11111', '2022-01-01');
SET FOREIGN_KEY_CHECKS = 1;

Output / Error:
Query OK, 1 row affected
Explanation: Temporarily disabling foreign key checks allows bootstrapping the initial interdependent records when strict NOT NULL circular constraints exist between two tables.
